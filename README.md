# 轻剪同步

本仓库包含两个独立构建的版本，使用同一主分支维护，不用长期分支区分产品：

| 版本 | 源码 | 状态 |
| --- | --- | --- |
| 小米电脑版（依赖已安装的小米电脑管家） | [`src/`](src/)；构建、安装脚本在仓库根目录 | 已在本机测试文字和图片双向同步 |
| 非小米电脑通用版（不单独安装电脑管家） | [`universal/`](universal/) | 实验版；用户在非小米电脑清理旧版后，确认一体安装版文字和图片双向同步成功 |

两版的界面代码目前各有副本，尚未抽成共享模块。不要使用长期分支隔离两版，否则共同修复容易分叉。

面向这台 Windows 11 电脑、小米 14 / 澎湃 OS 3 的本机适配版本。目标是在手机不安装其他应用的情况下，复用已经可用的小米互联通道，同步文字与图片。

## 当前状态

这是已在本机完成双向文字、图片实测的兼容版。

- 已验证：不加载管家界面、WebView 和 PcClipboard 程序，独立宿主可以完成互联初始化。
- 已验证：英文安装路径下，跨设备剪贴板收发服务注册返回成功。
- 已测得：本进程短时工作集约 100–114 MB，私有提交约 82–84 MB；保留的小米后台服务另外占用约 134 MB 工作集。工作集相加可能重复计算共享页面。图片传输瞬时峰值、长时间运行和整机重启后的占用尚未测量。
- 仍依赖：本机已安装的小米电脑管家 5.4.0.620 的互联库、账号服务和部分后台服务。不能卸载原管家。这不是完全脱离小米组件的协议重实现。
- 使用公共互联初始化入口时，部分非剪贴板模块也会初始化；本版本优先验证兼容性，尚未完成这些模块的进一步裁减。

## 安装和使用

在项目目录运行：

```powershell
.\install.ps1
```

程序安装在 `D:\Apps\LightClip`，桌面生成“轻剪同步”快捷方式。安装目录独立于 Codex 的应用缓存，避免打包环境重定向 LocalAppData 后导致快捷方式和自启动失效。重新安装会修复已开启的轻剪自启动路径，原来关闭自启动时则保持关闭。源码目录可以含中文，但运行目录必须是英文路径；本机实测中文路径会使小米互联库的调用方校验失败。

轻剪自身的数据均在安装目录下：`data\logs` 存放运行日志和界面错误，`data\status.txt` 存放当前状态，`data\cache` 是自身缓存目录，`data\temp` 用于本进程临时文件。本进程的 `TEMP` / `TMP` 指向这里，不修改 Windows 的用户或系统环境变量。切回管家时恢复原环境再启动管家；按用户确认，小米组件原有安装目录、共享缓存和原生日志保持原设置。

双击快捷方式后：

1. 退出原管家的界面、PcClipboard、MiPCAudio 和 MiSmartShareHandoff 用户进程。
2. 从原安装目录加载互联组件，使用原账号和配对关系。
3. 仅常驻一个托盘图标。单击图标打开快捷面板；再次双击桌面快捷方式也能打开面板。面板提供本进程内存、自启动开关和切回管家的入口。右键仍可使用原生菜单。

界面使用原生 Win32 绘制，跟随系统深浅色，支持 Tab 键导航。展开动画约 180 毫秒，自启动开关滑动约 120 毫秒；系统关闭动画时遵循系统设置。收起面板后停止所有界面计时器。新的桌面和托盘图标从独立图标文件加载，不改写小米签名宿主。

手机名称复用 `MiSmartShareClrWrapper` 的 `ConnectionUIWrapper` 和 `DeviceInfoUICLRWrapper` 回调，与原管家的设备名称来源一致：优先使用 `name`（可能是手机自定义名称），其次使用 `model_name`，都没有时显示“小米手机”。启动时通过 `HandleGetDeviceList` 获取一次现有设备列表，之后处理设备增加、移除、名称更新等通知，不增加网络扫描或常驻查询计时器。确认连接的手机优先；仅发现一台同账号手机时可以显示其名称，但不据此声称已经连接或同步成功；有多台候选时显示数量，不随意选取设备。手机信息仅保留在本进程内，状态文件仅显示名称和来源说明，不写入设备标识。

名称回调的本机实测已收到手机自定义名称。`scripts/DeviceNamesTests.cs` 通过直接调用真实回调适配器，检查名称更新、多台候选、连接优先级、断开、移除、空列表、型号回退和控制字符处理；这不替代真实手机改名或换机测试。

原管家安装目录中的文件、服务启动类型和原管家自启动项都不修改。主动重新打开原管家时，轻剪同步会退出并让出连接。

### 开机自启动

交付时已为本机开启。可以通过托盘“随 Windows 登录启动”关闭或重新开启；重新安装时可运行：

```powershell
.\install.ps1 -AutoStart
```

本工具只添加自己的 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\SyncClipboardLite` 项。登录后等待 30 秒再接管，以兼容原管家的已有启动流程。这里的“开机自启”是用户登录后启动。

### 恢复原管家

托盘选择“切回小米电脑管家”，或运行：

```powershell
& "$env:LOCALAPPDATA\SyncClipboardLite\SyncClipboardLite.exe" --restore
```

关闭本工具的自启动可在托盘取消勾选。卸载脚本只删除本工具自启动项、桌面快捷方式和安装目录，不卸载小米电脑管家。

## 构建方式

使用 Windows 自带的 .NET Framework C# 编译器生成程序集，在已安装的 .NET 8 运行时中执行，无需安装 SDK。

安装脚本从**本机现有安装**复制小米签名的 .NET 宿主作为 `SyncClipboardLite.exe`，不改动该文件；宿主加载本项目编译的 `XiaomiPcManager.dll`。文件名由宿主内部入口决定，这个 DLL 是本项目代码，不是原管家的界面程序集。

小米 DLL 保留在原目录，通过完整路径加载，不随项目分发。小米程序的授权不因本项目而改变。

`--check` 只检查版本、原生库 SHA-256 和运行路径，不启动同步、不退出原管家。更新原管家后，如果原生库与已测试版本不符，本程序拒绝加载，需重新适配。

## 数据与诊断

本工具的 `data\logs\status.log` / `data\status.txt` 只保存运行状态、设备名称、内存占用、路径和剪贴板变化次数，不保存剪贴板正文、图片、账号或配对凭据。小米组件仍可能按照其原有行为写入原生日志。

状态中的“互联库已启动”只表示初始化已返回，**不能替代手机端的同步测试**。剪贴板变化次数也包含电脑本地复制。

| 检查 | 结果 |
| --- | --- |
| 环境检查、原生库版本检查 | 通过 |
| 英文路径下剪贴板服务注册 | 通过，返回码 0 |
| 电脑文字到手机 | 通过，用户确认在手机粘贴出测试文字 |
| 手机文字到电脑 | 通过，电脑实际读取并匹配指定测试文字 |
| 电脑图片到手机 | 通过，用户确认在手机粘贴出四格图片 |
| 手机图片到电脑 | 通过，电脑实际读取到 1200×2670 的 DIB 图片数据，约 12.8 MB；未保存图片文件 |
| 切回原管家 | 通过，轻剪退出后原管家及其界面进程恢复 |
| 登录自启动 | 已设置，`--autostart` 延迟 30 秒后接管原管家的流程通过；未执行整机重启 |

2026-10-22 同机短时对比（包括保留的小米后台服务及管家的 WebView 子进程）：

| 指标 | 原整套管家 | 轻剪同步模式 |
| --- | ---: | ---: |
| 工作集合计 | 1016.6 MB | 234.2 MB |
| 私有提交合计 | 712.2 MB | 148.2 MB |

工作集相加会重复计算部分共享页面；私有提交也不等于当前驻留的物理内存。这是本次快照，不能当作长期占用保证。实测还确认原管家的 WebView 子进程已随接管退出，没有遗漏在轻剪统计之外。
